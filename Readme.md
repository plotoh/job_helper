# 🤖 HeadHunter Auto-Responder (hhparser)

> Полноценная система автоматического парсинга и откликов на вакансии hh.ru с веб-управлением, интеллектуальным
> скорингом и поддержкой нескольких аккаунтов.

[![Python](https://img.shields.io/badge/Python-3.11+-blue.svg)](https://www.python.org/downloads/)
[![FastAPI](https://img.shields.io/badge/FastAPI-0.104+-green.svg)](https://fastapi.tiangolo.com/)
[![Playwright](https://img.shields.io/badge/Playwright-1.x-green.svg)](https://playwright.dev/python/)
[![Docker](https://img.shields.io/badge/Docker-24+-blue.svg)](https://www.docker.com/)

---

## 🚀 Ключевая идея

**Парсинг → Скоринг → Автоотклик** – всё в одном асинхронном процессе.  
Система самостоятельно ищет вакансии, оценивает их релевантность по вашему профилю и отправляет отклики в течение
рабочего дня, соблюдая паузы и лимиты. Управление – через веб-интерфейс и Telegram-бота (опционально).

## 📦 Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/yourusername/hhparser.git
cd hhparser
```

### 2. Настройка переменных окружения

Скопируйте `.env.example` в `.env` (если есть) или создайте `.env` со следующими минимальными параметрами:

```env
# База данных
DB_HOST=postgres
DB_PORT=5432
DB_NAME=hhparser
DB_USER=user
DB_PASSWORD=pass

# Telegram (если нужен бот)
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_ADMIN_ID=ваш_id
TELEGRAM_USERS_IDS=[123, 456]   # список разрешённых ID

# Аккаунт hh.ru
TG_USERNAME=@ваш_телеграм_ник   # используется в письмах
RESUME_ID=ваш_id_резюме
PARSING_COOKIES_FILE=cookies/parsing.txt
COOKIES_DIR=cookies

# Настройки работы
WORK_START_HOUR=9
WORK_START_MINUTE=13
WORK_END_HOUR=18
WORK_END_MINUTE=41
DAILY_LIMIT_MIN=53
DAILY_LIMIT_MAX=97
```

Полный список параметров – в файле `app/config.py`.

### 3. Запуск через Docker Compose

```bash
docker-compose up -d --build
```

Сервисы:

- **postgres** – база данных (порт 5432)
- **worker** – основной воркер (парсинг + отклики)
- **web** – веб-интерфейс (порт 8000)

### 4. Доступ к веб-интерфейсу

Откройте в браузере: [http://localhost:8000](http://localhost:8000)

## ⚙️ Конфигурация через веб-интерфейс

На главной странице дашборда вы можете:

- **Управлять откликами** – глобально включить/отключить.
- **Включать/отключать уровни Junior/Senior** – отклики будут идти только на выбранные уровни (Regular всегда активен).
- **Запускать парсинг вне окон** – немедленно запустить сбор вакансий.
- **Пересчитывать скор** – для новых вакансий (без скора) или для всех (force).
- **Ставить аккаунт на паузу/возобновлять** – с указанием длительности.
- **Смотреть последние логи откликов** и переходить к полному логу.

## ➕ Добавление нового аккаунта hh.ru

Для работы воркера с аккаунтом нужно **три вещи**: cookies-файл, ID резюме и запись в БД через веб-интерфейс.

### 1. Получите cookies hh.ru в формате Netscape

Воркер использует cookies из браузера — так же, как если бы вы были залогинены на сайте.

**Самый простой способ:** установите в браузер расширение **«Get cookies.txt LOCALLY»** (Chrome / Firefox / Edge).

1. Зайдите на [hh.ru](https://hh.ru) и авторизуйтесь под нужным аккаунтом.
2. Откройте расширение → выберите **Netscape format** (именно он, не JSON).
3. Нажмите **Export** → сохраните файл.

Альтернатива без расширения: DevTools → Application → Cookies → руками выгрузить — **не рекомендую**, легко ошибиться в
формате.

### 2. Сохраните cookies под именем username аккаунта

В папке `cookies/` создайте файл с именем, совпадающим с полем `tg_username` будущего аккаунта:

```
cookies/{tg_username}.txt
```

**Примеры:**

- `tg_username = peyego1one` → файл `cookies/peyego1one.txt`
- `tg_username = second_account` → файл `cookies/second_account.txt`

> Имя файла должно точно совпадать с `tg_username` — воркер при старте ищет `cookies/{tg_username}.txt` и пропускает
> аккаунт, если файла нет.

**Проверьте**, что файл начинается так:

```
# Netscape HTTP Cookie File
...
.hh.ru  TRUE    /       FALSE   ...     hhtoken  ...
```

Если видите JSON (`[{...}]`) или другое — переделайте экспорт.

### 3. Получите `resume_id`

Зайдите на [hh.ru](https://hh.ru) под этим аккаунтом → **Резюме и профиль** → откройте нужное резюме → скопируйте ID из
URL:

```
https://hh.ru/resume/41bf6a4cff103235840039ed1f44433836306e
                     └───────────── resume_id ─────────────┘
```

### 4. Добавьте аккаунт через веб-интерфейс

1. Откройте дашборд: [http://localhost:8000](http://localhost:8000).
2. Нажмите **➕ Добавить аккаунт**.
3. Заполните поля:

| Поле                  | Обязательно | Описание                                                                                              |
|-----------------------|-------------|-------------------------------------------------------------------------------------------------------|
| **Telegram ID**       | ✅           | Число. Уникальный ID аккаунта (используется как `account_id` в БД). После сохранения изменить нельзя. |
| **Telegram username** | ✅           | Должен совпадать с именем файла cookies **без** `.txt`.                                               |
| **Resume ID**         | ✅           | ID резюме из URL hh.ru (см. шаг 3).                                                                   |
| **Аккаунт включён**   | —           | Галочка. Если снять — воркер не запустит этот аккаунт.                                                |

4. **Прокси** (опционально):
    - пусто → используется глобальный `PROXY_SERVER` из `.env`;
    - `-` → работать без прокси (даже если глобальный задан);
    - `host:port` → прокси только для этого аккаунта.

5. **Рабочее расписание, паузы, лимиты** (опционально):
    - пусто → значения из `.env` (глобальные `WORK_START_*`, `PAUSE_*`, `DAILY_LIMIT_*`);
    - заполнено → свои значения для этого аккаунта.

6. Нажмите **💾 Сохранить**.

### 5. Проверьте статус

На главной странице дашборда аккаунт появится в таблице. В столбце «Действия» доступны:

- **✏️** — редактировать аккаунт.
- **⏸** — пауза (30 мин, час, бессрочно — по желанию).
- **▶** — вернуться в обычный режим расписания.
- **⚡** — включить **быстрый режим** (игнорирует расписание и паузы).
- **📝** — открыть логи аккаунта в отдельном окне.

Убедитесь, что рядом с аккаунтом **нет** предупреждения «cookies не найден». Если есть — файл из шага 2 лежит не там или
назван неверно.

### 6. Перезапустите воркер

Воркер загружает список аккаунтов **при старте**. Чтобы новый аккаунт заработал:

```bash
docker compose restart worker
```

Через ~10 секунд в логах увидите:

```
Responses ENABLED. Found 2 enabled accounts.
Account 123456: прокси http://...
Account 707292488: без прокси
account.123456 - INFO - Starting worker for account 123456
```

### Частые проблемы

| Симптом                                 | Причина                                   | Решение                         |
|-----------------------------------------|-------------------------------------------|---------------------------------|
| `Cookies for account X not found`       | Файл не в `cookies/` или не совпадает имя | Проверьте `ls cookies/`         |
| `not_logged_in` в логе аккаунта         | Cookies протухли                          | Перегенерируйте файл (шаг 1)    |
| Все отклики падают в `auth_required`    | То же                                     | То же, + сменить пароль hh.ru   |
| Аккаунт не запускается после добавления | Воркер не перезапущен                     | `docker compose restart worker` |
| `cookies_exists: false` в UI            | Файл лежит не в `cookies/`                | Переместите                     |

### Обновление cookies

Cookies hh.ru живут несколько месяцев. Когда начнут истекать — в логах появится `auth_required`. Обновляйте так:

1. Заново экспортируйте cookies из браузера (шаг 1).
2. Перезапишите `cookies/{tg_username}.txt`.
3. `docker compose restart worker`.

Базу данных и настройки аккаунта при этом трогать **не нужно** — всё сохранится.

## 🌐 Настройка прокси

Прокси нужен, если:

- несколько аккаунтов работают с одного IP — hh.ru может связать их между собой;
- нужен разный гео-IP для разных аккаунтов (например, один через Москву, другой через Питер);
- работаете из страны, где hh.ru блокирует прямые запросы.

Прокси можно задать **двумя способами**:

| Уровень         | Где задаётся                                     | Для чего                           |
|-----------------|--------------------------------------------------|------------------------------------|
| **Глобальный**  | `.env` → `PROXY_SERVER`                          | Один прокси на все аккаунты сразу  |
| **Per-account** | Через веб-интерфейс, при редактировании аккаунта | Разные прокси для разных аккаунтов |

Приоритет: **per-account > глобальный**. Если у аккаунта свой прокси — глобальный игнорируется.

### Вариант A: глобальный прокси (все аккаунты)

1. Откройте `.env` в корне проекта (если файла нет — скопируйте из `.env.example` или создайте).
2. Добавьте строки:

```env
PROXY_SERVER=http://proxy.example.com:8080
PROXY_USERNAME=myuser
PROXY_PASSWORD=mypassword
```

3. Перезапустите воркер:

```bash
docker compose restart worker
```

4. В логе увидите:

```
Parsing will use proxy http://proxy.example.com:8080
Account 707292488: используется глобальный прокси
```

### Вариант B: разные прокси для разных аккаунтов

1. Откройте дашборд → **✏️** рядом с аккаунтом.
2. Заполните блок **🌐 Прокси**:

| Поле                   | Что вводить                                                             |
|------------------------|-------------------------------------------------------------------------|
| **Server (host:port)** | Полный URL прокси: `http://proxy.example.com:8080` (или `socks5://...`) |
| **Username**           | Логин (если прокси требует авторизацию)                                 |
| **Password**           | Пароль (если требует)                                                   |

3. Нажмите **💾 Сохранить**.
4. `docker compose restart worker`.

### Вариант C: аккаунт без прокси

Если **глобальный** `PROXY_SERVER` задан, но конкретный аккаунт должен работать **напрямую** — в поле **Server** введите
одиночный символ:

```
-
```

Это явный маркер «без прокси, даже если есть глобальный». Воркер увидит дефис и не подставит глобальный прокси.

> Поле нужно оставить **не пустым**. Пустое = «взять глобальный». Дефис = «без прокси». Это важно: пустую строку нельзя
> использовать как маркер, потому что она в БД хранится как `NULL`.

### Таблица поведения

| Глобальный `PROXY_SERVER` | Per-account `proxy_server` | Итог для аккаунта                |
|---------------------------|----------------------------|----------------------------------|
| задан                     | `NULL` (пусто в UI)        | используется глобальный          |
| задан                     | `-` (в UI)                 | без прокси                       |
| задан                     | `http://other:8080`        | используется `http://other:8080` |
| не задан                  | `NULL`                     | без прокси                       |
| не задан                  | `http://other:8080`        | используется `http://other:8080` |

### Формат URL прокси

Воркер понимает три схемы:

| Схема       | Пример                            | Когда использовать                  |
|-------------|-----------------------------------|-------------------------------------|
| `http://`   | `http://proxy.example.com:8080`   | Большинство HTTP/HTTPS прокси       |
| `https://`  | `https://proxy.example.com:8443`  | Прокси с TLS                        |
| `socks5://` | `socks5://proxy.example.com:1080` | SOCKS5 (в том числе с авторизацией) |

**С логином и паролем** — вводите их в отдельных полях (Username/Password), **не пихайте в URL**. Playwright склеивает
их сам.

Неверно:

```
Server: http://user:pass@proxy.example.com:8080
```

Верно:

```
Server: http://proxy.example.com:8080
Username: user
Password: pass
```

### Проверка, что прокси работает

**Способ 1 — по логам.** После `docker compose restart worker`:

```
# Успех:
Account 707292488: прокси http://proxy.example.com:8080
✅ Кнопка отклика: a[data-qa="vacancy-response-link-top"]

# Ошибка прокси:
💥 Ошибка при отклике на https://...: net::ERR_PROXY_CONNECTION_FAILED
💥 Ошибка при отклике на https://...: net::ERR_TUNNEL_CONNECTION_FAILED
💥 Ошибка при отклике на https://...: net::ERR_PROXY_AUTH_UNSUPPORTED
```

**Способ 2 — вручную через `curl`** (на хосте, где запущен Docker):

```powershell
# Windows PowerShell
curl.exe -x http://user:pass@proxy.example.com:8080 https://api.ipify.org

# Должен вернуть IP прокси, не ваш домашний.
```

### Частые ошибки и что они значат

| Ошибка                         | Причина                                          | Решение                                         |
|--------------------------------|--------------------------------------------------|-------------------------------------------------|
| `ERR_PROXY_CONNECTION_FAILED`  | Прокси недоступен                                | Проверьте host:port, доступность с вашей машины |
| `ERR_PROXY_AUTH_UNSUPPORTED`   | Прокси требует авторизацию, но креды не переданы | Заполните Username/Password                     |
| `ERR_TUNNEL_CONNECTION_FAILED` | Прокси не пропускает HTTPS                       | Проверьте, поддерживает ли прокси `CONNECT`     |
| `ERR_NAME_NOT_RESOLVED`        | DNS через прокси не резолвится                   | Попробуйте SOCKS5 вместо HTTP                   |
| `ERR_CONNECTION_TIMED_OUT`     | Долгий отклик или блокировка                     | Проверьте через `curl` вручную                  |

### Что прокси **не** решает

- **hh.ru всё равно может забанить** — если паттерн поведения подозрительный. Прокси скрывает IP, но не отпечаток
  браузера (user-agent, TLS, canvas). Для серьёзной анонимности нужен `playwright-stealth` — это **вне рамок данного
  проекта**.
- **Не поможет при auth_required**. Если сессия истекла — прокси не восстановит её. Обновляйте cookies.
- **Прокси не ускоряет отклик**. Иногда замедляет — особенно если прокси в другом регионе.

### Рекомендации

1. **Один аккаунт = один прокси.** Если два аккаунта ходят через один IP, hh.ru может связать их и забанить оба.
2. **Резидентные прокси лучше датацентровых** — hh.ru иногда блокирует DC-подсети.
3. **Прокси в РФ** — если целевые вакансии в РФ, отклики через VPN-IP могут выглядеть подозрительно.
4. **Не покупайте дешёвые «100 прокси за $5»** — они почти все уже в базах hh.ru.
5. **Проверяйте прокси перед запуском** через `curl` — сэкономите себе час отладки.

# Обнуление счётчика used_count для всех вакансий

docker exec -it hhparser_db psql -U user -d hhparser -c "UPDATE vacancies SET used_count = 0;"

# ✅ Проверка результата

docker exec -it hhparser_db psql -U user -d hhparser -c "SELECT used_count, COUNT(*) FROM vacancies GROUP BY used_count
ORDER BY used_count;"

# Обнуление счётчика страниц поиска
# Посмотреть текущее значение

docker exec -it hhparser_db psql -U user -d hhparser -c "SELECT id, search_url, last_page FROM parsing_progress;"

# Обнулить last_page для всех записей (все URL)

docker exec -it hhparser_db psql -U user -d hhparser -c "UPDATE parsing_progress SET last_page = 0;"

# Проверка

docker exec -it hhparser_db psql -U user -d hhparser -c "SELECT id, last_page FROM parsing_progress;"

# Только логи одного аккаунта (по строке account_id)

docker compose logs -f worker | Select-String "Account 707292488"

# Только парсер

docker compose logs -f worker | Select-String "parsing_scheduler"

# Только отклики

docker compose logs -f worker | Select-String "hh_response|account_worker"
