# 🤖 HeadHunter Parser Bot (hhparser)

> Telegram-бот для автоматизации парсинга вакансий и откликов на [hh.ru](https://hh.ru) с поддержкой нескольких аккаунтов, гибкой фильтрацией, планировщиком и ежедневными отчётами.

## 🚀 Возможности

| Функция                            | Описание                                                                                                                                                   |
|------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **🔍 Парсинг вакансий**            | Автоматический сбор вакансий по заданному URL-фильтру в течение дня (5 временных окон).                                                                    |
| **🎯 Интеллектуальная фильтрация** | Классификация вакансий на **regular**, **junior**, **senior** и **reject** на основе регулярных выражений. Сохранение отфильтрованных в отдельные таблицы. |
| **👥 Мультиаккаунтность**          | Поддержка нескольких аккаунтов hh.ru – каждый со своим файлом cookies, резюме и настройками.                                                               |
| **✉️ Генерация писем**             | Шаблонизация сопроводительных писем с переменными (`{vacancy_name}`, `{tg_username}`) и случайным выбором вариантов (`{Здравствуйте|Привет}`).             |
| **⏰ Автоотклики**                  | Отправка откликов по расписанию с учётом дневного лимита, случайных пауз и рабочих часов.                                                                  |
| **📊 Telegram-бот**                | Просмотр статистики (парсинг за час/день, прогресс аккаунтов), список пользователей, персональные отчёты об ошибках.                                       |
| **🧹 Очистка устаревших вакансий** | Автоматическое удаление или деактивация вакансий старше N дней или использованных более N раз (настраивается).                                             |
| **📝 Логирование отклонённых**     | Запись отклонённых вакансий в текстовые файлы (`logs/rejected_YYYY-MM-DD.txt`) для анализа.                                                                |
| **🌐 Прокси**                      | Поддержка единого прокси-сервера для всех аккаунтов (настраивается через `.env`).                                                                          |
| **🔄 Планировщик**                 | Все задачи (парсинг, отклики, отчёты, очистка) выполняются асинхронно внутри одного процесса – без внешних брокеров.                                       |
| **🐳 Docker**                      | Готовая контейнеризация для быстрого развёртывания (worker + PostgreSQL).                                                                                  |


## 📦 Установка и запуск

### 🔧 Локальная разработка

#### 1. Клонирование репозитория
```bash
git clone https://github.com/yourusername/hhparser.git
cd hhparser
```

#### 2. Создание виртуального окружения и установка зависимостей
```bash
python -m venv .venv
source .venv/bin/activate   # или .venv\Scripts\activate на Windows
pip install -r requirements.txt
```

> Если вы используете Poetry, выполните `poetry install` вместо `pip`.

#### 3. Настройка переменных окружения
Создайте файл `.env` в корне проекта (можно скопировать из примера, если он есть):
```bash
cp .env.example .env   # если есть
```
Заполните обязательные параметры (см. раздел [⚙️ Конфигурация](#-конфигурация)).

#### 4. База данных
Убедитесь, что PostgreSQL запущен (локально или в Docker). При первом запуске таблицы создадутся автоматически через `Base.metadata.create_all`.  
**Важно:** если вы обновляете существующую базу с предыдущей версии, выполните вручную ALTER-запросы (см. раздел [Миграции](#-миграции) в документации).

#### 5. Запуск
Запустите **воркер** (главный процесс, который выполняет парсинг, отклики, отчёты):
```bash
python -m app.scheduler.worker
```

Запустите **Telegram-бота** (в отдельном терминале или как отдельный сервис):
```bash
python -m app.bot.bot
```

### 🐳 Запуск в Docker

#### 1. Подготовка
Убедитесь, что `.env` настроен (особенно переменные для Telegram и БД).

#### 2. Запуск всех сервисов
```bash
docker-compose up -d --build
```

Контейнеры:

| Сервис     | Описание                           | Порт   |
|------------|------------------------------------|--------|
| `postgres` | База данных                        | `5432` |
| `worker`   | Основной воркер (парсинг+отклики)  | —      |
| `bot`      | Telegram-бот (закомментирован в `docker-compose.yaml`, при необходимости раскомментируйте) | — |

#### 3. Просмотр логов
```bash
docker-compose logs -f worker
docker-compose logs -f postgres
```

#### 4. Остановка
```bash
docker-compose down
```

## ⚙️ Конфигурация

Все настройки задаются через переменные окружения (файл `.env`).

### Обязательные параметры (Telegram)
```env
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_ADMIN_ID=ваш_telegram_id
TELEGRAM_USERS_IDS=[123, 456]   # список ID разрешённых пользователей (JSON или через запятую)
```

### База данных
```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=hhparser
DB_USER=user
DB_PASSWORD=pass
```

### Параметры парсинга
```env
HH_SEARCH_URL=https://hh.ru/search/vacancy?text=Python+Developer&area=1
MAX_CONCURRENT=5               # одновременно парсимых вакансий
PAGES_PER_WINDOW=3             # страниц за одно окно
DAILY_PARSING_LIMIT=100        # макс. новых вакансий в день
VACANCY_TTL_DAYS=7             # срок годности вакансии (дни)
MAX_USES_PER_VACANCY=2         # сколько аккаунтов может откликнуться
```

### Рабочее время и паузы
```env
WORK_START_HOUR=9
WORK_START_MINUTE=13
WORK_END_HOUR=18
WORK_END_MINUTE=41
PAUSE_COUNT=3                  # количество пауз в день
PAUSE_MIN_MINUTES=30
PAUSE_MAX_MINUTES=60
DAILY_LIMIT_MIN=53             # минимальный дневной лимит откликов
DAILY_LIMIT_MAX=97
```

### Прокси (опционально)
```env
PROXY_SERVER=http://proxy.example.com:8080
PROXY_USERNAME=user
PROXY_PASSWORD=pass
```

### Пути к файлам
```env
COOKIES_DIR=cookies
PARSING_COOKIES_FILE=cookies/parsing.txt
MESSAGE_TEMPLATE_FILE=app/message_template.txt
REJECTED_LOGS_DIR=logs
```

### Отчёты об ошибках
```env
ERROR_REPORT_HOUR=19
ERROR_REPORT_MINUTE=0
```

## 📖 Использование

### Команды бота

| Команда / Кнопка          | Описание |
|---------------------------|----------|
| `/start`                  | Приветствие и главное меню (клавиатура). |
| `📈 Моя статистика`       | Показывает, сколько откликов сделано сегодня, лимит, количество ошибок за час. |
| `❌ Мои ошибки`           | Список вакансий (до 10), на которые не удалось откликнуться (с ссылками). |
| `/help`                   | Справка по командам. |
| **Администратор:**        | |
| `📊 Отчёт`                | Сводка по парсингу за час и день, статусы всех аккаунтов (сделано/лимит, ошибки, паузы). |
| `👥 Пользователи`         | Список зарегистрированных аккаунтов с их резюме. |

> **Важно:** доступ к боту имеют только пользователи, перечисленные в `TELEGRAM_USERS_IDS` и администратор.

### Администратор
Администратор (ID из `TELEGRAM_ADMIN_ID`) имеет дополнительные возможности:
- `/report` или кнопка **📊 Отчёт** – общая статистика.
- `/users` или кнопка **👥 Пользователи** – список аккаунтов.

## 🧩 Особенности

### 📅 Планировщик парсинга
Парсинг выполняется в 5 окон в течение дня:
- 9:00–10:00
- 12:30–13:00
- 13:00–14:00
- 15:00–16:00
- 21:00–23:00

В каждом окне обрабатывается до `PAGES_PER_WINDOW` страниц, но парсинг останавливается при достижении дневного лимита (`DAILY_PARSING_LIMIT`).

### 📂 Логирование отклонённых вакансий
Все вакансии, не прошедшие фильтр, записываются в файл `logs/rejected_YYYY-MM-DD.txt` в формате:
```
Название вакансии | Ссылка
```

### 🧹 Очистка устаревших
Каждую ночь (в 00:05) запускается задача, которая помечает `is_actual=False` для вакансий:
- старше `VACANCY_TTL_DAYS` дней;
- использованных более `MAX_USES_PER_VACANCY` раз (откликнулись несколько аккаунтов).

Такие вакансии больше не участвуют в откликах.

### 📧 Ежедневный отчёт об ошибках
В заданное время (по умолчанию 19:00) каждому аккаунту отправляется список ошибок отклика, которые ещё не были отправлены. После отправки они помечаются как `reported` и больше не дублируются.

### 🔐 Прокси
Если задан `PROXY_SERVER`, он будет использоваться для всех контекстов браузера (и для парсинга, и для откликов). Аутентификация прокси поддерживается через `PROXY_USERNAME` и `PROXY_PASSWORD`.
